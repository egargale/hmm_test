## Agent Brief

**Category:** bug
**Summary:** Fix forecast off-by-one in `_build_markov_stats` and add a 5×5 statistical evaluation harness that pins the invariant in CI.

**Current behavior:**
The `MarkovStats.current_probs` field returned by `_build_markov_stats` is set to `transmat[last_regime]` (a row of `T`). `forecast_n_steps` then computes `current_probs @ T^n`, so `forecast.1_step` is actually `T^2[last_regime, :]` (a 2-step distribution), `forecast.5_step` is 6-step, and `forecast.20_step` is 21-step. The bug is invisible on HMM engines because their persistence is ≈ 1.0 (so `T[i] @ T ≈ T[i] ≈ e_i @ T`), but the threshold engine shows deltas of up to **Δ=0.18** between `forecast.1_step` and `next_state_probabilities` on BTC, SPY, NVDA, XLE. The SKILL.md contract states these fields should be the same.

**Desired behavior:**
`current_probs` must be the one-hot unit vector for the current regime (`e_i`), not a row of the transition matrix. With this fix, `forecast.1_step` equals `T[current_regime, :]` exactly, and the higher-horizon forecasts advance by the correct number of steps. A 5-ticker × 5-engine pytest harness pins this invariant and a small set of statistical sanity checks in CI.

**Key interfaces:**
- `_build_markov_stats(regimes, price_index) -> MarkovStats` — the function whose `current_probs` field carries the bug. Fix the assignment; respect the shape of `transmat` (3×3 by default, 2×2 after the documented mid-stream degeneration path in ADR-0018). The construction should be robust to either shape.
- `MarkovStats.current_probs: np.ndarray` — its semantics change from "1-step distribution" to "one-hot for current regime". `MarkovStats.signal` and the `next_state_probabilities` JSON field are *not* affected (the wire-format contract for those is unchanged).
- `forecast_n_steps(transmat, current_probs, n)` — no change needed; it does `current_probs @ T^n`, which is correct once `current_probs` is one-hot.
- The transition-matrix field on the `MarkovStats` dataclass, the JSON `next_state_probabilities` field, the `signal` field, and the `verdict` synthesizer are *unchanged* by this fix.
